IoTIDR / 嵌入式 · 物联网

物联网
智能晾衣架

以 STM32 为设备核心，采集温湿度与相对光照，驱动晾衣架按四个档位展开。LCD、红外遥控与 Android 应用共同参与控制，环境保护策略提供自动收架能力。

01

感知、控制与交互

将环境信息、设备动作和控制端连接成一套完整的应用逻辑。

SENSING / 环境感知

温湿度与光照采集

DHT11 提供温度与湿度信息，光敏传感器通过 ADC 采样。十次采样平均得到相对光照刻度，数据同时服务界面展示与保护判断。

MOTION / 设备动作

四档展开控制

28BYJ48 步进电机与 ULN2003 驱动晾衣架动作。根据目标档位和当前软件位置计算移动距离，统一管理运动、完成与拒绝状态。

DISPLAY / 本地交互

LCD 触摸与红外遥控

TFTLCD 显示传感器、网络和电机状态，触摸入口控制档位与两路灯光；红外数字 1–4 对应四个展开档位。

CONNECTIVITY / 物联网

机智云与 Android 控制端

WiFi 模块经 USART3 与主控交换机智云数据点。Android 端显示环境数据、下发档位与灯光指令，支持设备发现、绑定及配网流程。

PROTECTION / 环境策略

高湿环境自动收架

结合网络时间、湿度和白天光照条件触发保护，向统一控制入口请求 1/4 档。保护期间限制进一步展开，界面与 APP 展示触发状态。

FEEDBACK / 状态反馈

灯光、提示与设备状态

两路 LED 可独立控制，蜂鸣器提供操作反馈。系统维护采样有效性、网络连接、机械参考和运动状态，让指令与设备状态保持一致。

02

从设备到应用的系统架构

传感器与本地交互进入主控，应用层管理设备状态；WiFi 模块承担设备与机智云之间的通信。

03

四档展开与环境保护

多种控制来源共享同一套设备状态，控制请求先经过状态检查，再进入电机执行。

条形表示档位比例。档位 0 对应 1/4 开，保护动作请求这一档位。

一个控制入口，多种操作方式

Android 档位选择、LCD 触摸、红外数字键以及自动保护均提交目标档位。应用层检查机械参考、忙状态与保护条件，减少重复指令造成的额外动作。

位置状态与运动完成

电机上电后需要确认机械参考位置，随后按步数估算位置。运动状态与已完成档位分别维护，动作结束后再更新完成状态。

本地配网与灯光操作

LCD 提供 AirLink、SoftAP 与 WiFi 重置入口，红外支持配网及复位操作。两路 LED 独立下发与回显，WiFi 重置需要确认。

当前位置来自机械参考与软件步数估计。系统没有编码器或自动归零反馈，档位比例不等同于闭环测量的机械行程。

白天 / 08:00–18:59

高湿度 + 低光照

湿度超过 85%，且相对光照低于 20 时，触发环境保护。

保护状态生效 · 请求 1/4 档

夜间 / 19:00–次日 07:59

高湿度

湿度超过 85% 时触发环境保护，夜间不以光照作为附加条件。

保护状态生效 · 请求 1/4 档

保护判断依赖有效的网络通信、网络时间、传感器新鲜数据和机械参考。光照使用 0–100 相对刻度；当前项目使用这些环境条件作为保护依据。

04

设备与应用共享的数据

七个机智云数据点定义控制指令和设备上报内容，板端与 Android 应用保持一致。

机智云设备数据点
数据点方向内容
LED0下发 / 回显第一路灯光开关
LED1下发 / 回显第二路灯光开关
degree下发 / 回显四档展开，0–3 对应 1/4 开至全开
careMODE设备上报环境保护是否触发，由设备计算
light设备上报0–100 相对光照刻度
humidity设备上报相对湿度，单位 %RH
tempr设备上报温度，单位 °C；保留协议中的原标识名
05

实现情况

项目包含板端固件与 Android 控制工程。 环境采集、四档控制、LCD/触摸、红外、灯光、机智云协议与保护逻辑均有对应实现。

板端完整固件已构建，协议、电机与 LCD/触摸的主机回归通过；已有电机点动和部分红外按键的实物反馈。完整机械行程、最新按键映射与手机—云端—设备的整链路效果仍需实物确认。
