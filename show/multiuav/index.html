01

三个部分，组成一个系统

后端计算网络行为，中间件承接数据与控制，前端把运行状态呈现给用户。

SIMULATION BACKEND

ns-3 仿真后端

用 C++ 运行节点移动、分簇、路由与 MAC 模型，产生节点状态和性能指标。

  • 支持命令行参数，或从中间件领取仿真配置。
  • 接口模块采集状态，Connector 按消息定义封装为 JSON。
  • 后台 HTTP worker 向中间件上报，携带场景与快照信息。
DATA & CONTROL SERVICE

C++ 中间件

用 HTTP 接收数据和配置，用 RabbitMQ 衔接数据生产与消费，用 WebSocket 提供订阅推送。

  • 校验配置、映射算法名称，按场景暂存待领取参数。
  • 保留消息元数据，按队列消费并整理节点快照。
  • 提供独立的 MariaDB 设备信息存取接口；服务以 Docker 组织。
BROWSER FRONTEND

浏览器前端

提交仿真参数，解析返回消息，按场景维护节点与指标状态，形成可交互的观察工作台。

  • 按 type 与 sceneId 分发消息，排除过期节点快照。
  • Three.js 显示节点与分簇关系，Chart.js 显示指标历史。
  • 支持详情、定位、浏览器本地保存与文件导出。

STEP 01

仿真产生状态

查看每一站的输入、转换与输出。

仿真对象 → 节点／指标结构
C++ 状态对象示例字段 · 非实时抓包

Protobuf 定义字段；接口实际传输 JSON 文本。

sceneId / algorithm

说明数据属于哪个场景、哪种算法，让同一服务处理的消息有明确归属。

snapshot / snapshotId

区分完整快照及其顺序；前端据此更新节点集合，忽略已处理的旧快照。

type / data

type 决定处理分支，data 承载节点或指标。传递过程中保留外层元数据。

04

系统传递哪些数据

节点快照描述空间与分簇状态，指标消息描述运行表现；具体上报类别随仿真模块启用。

指标与观察对象
层面展示内容观察对象
节点位置、速度、角色、能量、簇头、权重、IP节点运动与分簇归属
路由平均时延、丢包率、收敛时间、平均吞吐量端到端通信表现
MAC时延、信道利用率、丢包率、吞吐量信道访问与 QoS 优先级
分簇簇首与成员平均生命周期、簇维护消息、簇首声明消息、Guest 维护消息分簇稳定性与维护开销
ALGORITHM & PROTOCOL

当前控制台提供 WOA、DFP-LR-WOCA、DFP-LR-WOCA-no-RK 三种分簇算法；MAC 支持 eemac 与 qosmac。不同演示场景用于展示界面能力，曲线差异由模拟函数生成。
